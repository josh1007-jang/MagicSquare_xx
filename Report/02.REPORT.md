### 리뷰 결과 — 빠지거나 어긋난 항목 (9건)

| 구분 | 워크북 | validate_lines 계약 | 차이 |
|------|--------|---------------------|------|
| Input | `목표 합 = 34`를 Input 항목으로 기술 | `validate_lines(grid)` 단일 인자, 34는 `MAGIC_CONSTANT` 상수 | **어긋남** |
| Input | `빈칸 2개`를 Input 조건으로 명시 | 0이 1개 이상이면 `incomplete`; 빈칸 개수=2 검증 없음 | **어긋남** |
| Output | `pass` / `fail`만 암시 | `status: "incomplete"` (0 포함 격자) | **빠짐** |
| Output | **10개 항목별 합** 출력 | fail/incomplete 시 **틀린 줄만**; pass 시 10선 sum 목록 없음 | **어긋남** |
| Output | 실패 시 행/열/대각선 **식별**만 | 실패 줄 ID + **해당 합 값** (참조 PRD F4) | **빠짐** |
| Output | 줄 식별 방식 미정 | `R1~R4`, `C1~C4`, `D1`, `D2` | **빠짐** |
| 성공기준 2 | ECB·슬라이드 과제 **재현 시나리오** Test Loop 포함 | T1/G1에 구체 4×4 픽스처 정의됨 | **빠짐** — 워크북 Test Loop에 픽스처 격자 없음 |
| 성공기준 3 | 행·열만 **부분 검증** 시 Rule 위반 **감지** (TC3) | `validate_lines`는 항상 10선 전검; 부분 실행 감지 API 없음 | **어긋남** |
| 성공기준 (전반) | 3개 기준 모두 | R5/AC4: 빈칸(0) → `incomplete` | **빠짐** |

### 일치 항목 (리뷰 제외)

- Role / Goal: 4×4 부분 마방진, 10항목, 합 34, 실패 시 줄 식별
- 성공기준 1: 대각선 2개 포함, 행·열 OK·대각선 1개 fail → fail + 대각선 식별
